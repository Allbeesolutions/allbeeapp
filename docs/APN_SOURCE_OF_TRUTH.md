# ALLBEE APN — Source of Truth Matrix

Every APN concept has exactly **one authoritative owner** (table/function). Derived surfaces
(wallets, portals, AI context) must never become second sources of truth — they are recomputed
or read-only projections of the owner below.

Conventions:

- **Authoritative Source** = the row set / function that OWNS the truth.
- **Read Surface** = how the rest of the system reads it (RLS policy or RPC).
- **Write Surface** = the ONLY legal way it is written (always a role-gated SECURITY DEFINER
  function or an engine trigger — never a raw client UPDATE).
- **Historical Rule** = what happens when history would otherwise be rewritten.
- **Security Boundary** = who may write, and the enforcement mechanism.

## The one rule that follows from this matrix

> **Wallets and portals are projections. The ledger and the engine functions are the truth.**
> If a derived number disagrees with the ledger, the refresh is broken — never "fix" the number
> by writing the wallet directly. Re-run the relevant refresh function (`apn_consolidated_wallet_refresh`,
> `apn_withdrawal_refresh_wallet`, `apn_referral_refresh_wallet`) or trace which source row
> changed.
